## 产品主题、受众与页面任务

主题是“离线投标文档元数据取证”。用户是招投标审查人员，演示受众是管理者。

各状态只承担一个主要任务：

1. 选择状态帮助用户确定待核验目录，并说明文件不会上传。
2. 目录确认状态帮助用户确认识别出的投标人、文件数量和异常边界。
3. 扫描状态帮助用户理解当前阶段、完成度和停止行为。
4. 报告状态帮助用户先判断风险结论，再进入证据。
5. 元数据明细帮助用户把风险结论追溯到具体投标人、文件、字段和解析器。

## 共同交付形态

原型放在 `desktop/mock/design-spec-variants/`，与正式 Renderer 隔离。入口为
`index.html`，可直接使用 Chromium 浏览器打开，不需要安装依赖或启动服务器。

入口提供三套方案卡片，也允许在任意状态切换版本：

- `#guided`：A，引导式核验工作台。
- `#verdict`：B，结论先行审查报告。
- `#matrix`：C，证据矩阵控制台。

版本切换保留当前业务状态。例如从 B 的报告页切到 C 后，仍停留在报告页，便于同屏公平比较。刷新页面恢复当前版本和演示进度；“重新开始演示”清空状态。

原型使用普通 HTML、CSS 和无依赖 JavaScript。不得引入框架、外链字体、外链图标、远程图片或 CDN。页面通过 `file://` 打开时仍需完整工作。

## 共同设计系统

### 色彩

颜色完全服从设计规范，不另造品牌色：

- `primary`：`#034ed6`，只用于主按钮、链接、激活态和少量关键标签。
- `ink`：`#141928`，用于标题和主文字。
- `sub`：`#5d6579`，用于说明和次级信息。
- `line`：`#e8eaf0`，用于浅色区域的发丝分隔。
- `dark`：`#0e1226`，用于唯一的深色真实数据面板。
- `danger`：`#c93438`，只用于跨投标人的高风险身份痕迹。
- `warning`：`#a85c00`，只用于需要人工复核的模板或时间线索。
- `success`：`#15803d`，只用于完成、通过和无异常状态。

所有品牌派生色来自 `--primary`。换肤只修改这一个入口，并复用规范的
`color-mix()`、OKLCH 和静态回退三层写法。语义色、中性色和平台识别色不跟随换肤。

柔光只在页面顶部 560px 范围内出现，底部自然过渡到纯白。页面主体、浅色卡片和页脚不得出现氛围渐变。

### 字体

离线约束不允许下载字体，使用规范指定的角色分工：

- 中文标题和正文：`PingFang SC`、`Hiragino Sans GB`、`Microsoft YaHei`、系统无衬线回退。
- 数量、日期、报告编号、步骤号和字段键：`ui-monospace`、`SF Mono`、Menlo、Consolas 回退。
- 页面只使用 400、500、600、700 四档字重，关键层级同时通过字号、色彩和空间表达，不只依赖字重。

### 空间、边界与阴影

- 使用规范的 4px 空间基准和 7–14px 圆角序列。
- 浅色卡片零阴影，以 `--line`、`--line-soft` 和留白分区。
- 只有深色数据面板可使用 `--shadow-panel`。
- 浮动主题面板和 Toast 可分别使用规范的 `--shadow-float`、`--shadow-pop`。
- 可点击元素最小命中区为 28px，主要按钮不小于 36px 高。

### 图标

所有图标从用户提供的 33 枚 SVG 注册表中选择。每个页面只内嵌实际使用的
`<symbol>`，路径逐字复制，不私造图标，不使用 emoji、图标字体或第三方图库。

图标使用 `currentColor`、24px 画布、1.8px 圆头描边；页面只使用规范允许的 13、14、15、16 和 20px 尺寸档。

### 动效

每套方案只保留一个标志性运动：

- A：当前步骤标记沿流程轨道移动。
- B：报告完成时，结论区和证据摘要按阅读顺序一次性进入。
- C：选中矩阵命中项后，对应行列和证据链同步聚焦。

扫描过程统一使用真实阶段进度和低调扫描线，不使用发光、呼吸、粒子或装饰性波形。`prefers-reduced-motion: reduce` 下关闭位移动画和自动进入效果，状态仍通过文字、边框和进度值表达。

- 投标人：华远建设、启明工程、中筑科技、新科咨询。
- 文件：每家 4 份，共 16 份 PDF、Word 和 Excel 文档。
- 解析结果：16/16 完成，148 条归一化元数据，三种解析器交叉取证。
- 高风险身份痕迹：2 组。
  - 作者“王磊”跨华远建设与启明工程出现。
  - 最后修改者“zhangmin”跨中筑科技与新科咨询出现。
- 待复核线索：3 组。
  - 跨投标人使用相同模板名称。
  - 两份文档创建时间相差 87 秒。
  - 两份文档的生成应用与版本组合相同。

姓名、公司和文件名均为演示数据，不引用真实文件、真实报告或用户目录。高风险与待复核必须明确区分；相同软件或模板不得写成已经认定的串标结论。

## 共同交互闭环

### 选择与目录确认

首屏提供两个动作：

- “载入演示项目”立即加载固定的 4 家投标人、16 份文档，是老板演示的主路径。
- “选择本机目录”使用 `<input type="file" webkitdirectory>` 读取浏览器授权后的文件名、相对路径、大小和扩展名，只用于计算投标人分组与文件数量，不读取文档正文，不上传文件，也不生成真实元数据。

若浏览器不支持目录选择，保留演示项目按钮并显示明确说明。目录确认页可更换目录或开始核验。

### 模拟扫描

扫描按固定但可信的阶段推进：

1. 校验文件清单。
2. 识别 PDF、OLE 和 OPC 容器。
3. 运行原生解析、Apache 和 ExifTool 模拟阶段。
4. 归一化证据并比较跨投标人痕迹。
5. 生成报告。

进度可停止。停止后显示“核验已停止，未生成报告”，并允许重新开始；不把停止伪装成失败。扫描时保留阶段文字、已处理文件数、百分比和预计剩余时间。

### 核验报告

报告页提供：

- 高风险、待复核、全部三种筛选。
- 可展开的证据条目。
- 从条目跳到对应元数据字段的动作。
- 查看全部元数据。
- 返回重新选择和重新核验。
- 一键切换 A、B、C 版本，并保留当前报告状态。

### 元数据明细

明细页提供：

- 按投标人筛选。
- 按文件名或字段值检索。
- “只看跨投标人重复”开关。
- 文件卡展开与收起。
- 风险字段的来源、原始值、归一化值、解析器和关联文件。
- 回到报告时保持原筛选与滚动语义，不重新扫描。

## A：引导式核验工作台

### 设计目标

让第一次看到产品的人始终知道“现在在哪一步、已经完成什么、下一步做什么”。它最强调产品闭环和过程可信度。

### 布局

```text
┌ 顶栏：品牌 / 当前项目 / 版本切换 / 主题 ───────────────┐
│ 页头柔光：状态标题 + 一句话说明 + 当前步骤             │
├─────────────┬───────────────────────────────────────┤
│ 01 选择目录  │                                       │
│ 02 文件识别  │ 当前步骤的主要内容                     │
│ 03 离线扫描  │                                       │
│ 04 核验报告  │ 深色数据面板 / 报告卡 / 下一步动作     │
│ 05 元数据    │                                       │
└─────────────┴───────────────────────────────────────┘
```

左侧步骤轨道是本方案的标志性元素。步骤编号是真实流程，不是装饰编号。选择和扫描阶段使用较窄内容区，报告和明细阶段自动扩展主内容宽度。

报告首屏先呈现深色完成面板，再使用四块无阴影任务卡分别说明高风险、待复核、覆盖情况和下一步。元数据页延续左侧轨道，并在步骤 05 高亮。

### 取舍

优势是完整、稳健、易讲解；代价是风险结论不像 B 那样占据第一视觉位置。为避免流程控件抢夺注意力，轨道保持窄、低彩度，只有当前步骤使用主色。

## B：结论先行审查报告

### 设计目标

让管理者在五秒内理解“发现了什么、严重程度如何、为什么可信”，再决定是否下钻。

### 布局

```text
┌ 顶栏：品牌 / 报告 / 元数据 / 版本切换 / 主题 ─────────┐
│ 页头柔光：一句完整风险结论 + 项目摘要                  │
├──────────────────────────┬──────────────────────────┤
│ 结论带：建议重点复核       │ 4 个紧凑统计               │
├──────────────────────────┼──────────────────────────┤
│ 风险证据时间线             │ 深色“3/3 解析器”可信度面板 │
│ 待复核线索                 │ 报告范围与生成信息         │
└──────────────────────────┴──────────────────────────┘
```

完整句子“本次核验发现 2 处高风险身份痕迹”是视觉主角。红色只出现在左侧风险边线、风险标签和证据命中值，不铺成大面积告警底。

深色面板不重复展示普通 KPI，而是回答“为什么可信”：三种解析器是否一致、证据是否可追溯、解析覆盖是否完整。报告下钻后，元数据明细默认定位到触发结论的字段。

### 取舍

优势是最适合老板演示和报告截图；代价是扫描流程存在感较弱。选择和扫描阶段通过紧凑顶部阶段条补足过程信息，但不把流程轨道带进报告正文。

## C：证据矩阵控制台

### 设计目标

最大化专业审查人员比较跨投标人、跨文件和跨字段证据的效率，同时保持管理者可以先看到摘要。

### 布局

```text
┌ 顶栏：品牌 / 证据矩阵 / 核验记录 / 版本切换 / 主题 ───┐
│ 页头柔光：项目摘要 + 风险/复核/覆盖数字                │
├────────────────┬────────────────────────────────────┤
│ 投标人          │ 深色摘要条                          │
│ ├ 文件           ├────────────────────────────────────┤
│ ├ 文件           │ 字段 × 投标人矩阵                   │
│ 投标人          │ 选中命中项的证据链与来源抽屉         │
│ └ 文件           │                                    │
└────────────────┴────────────────────────────────────┘
```

字段与投标人的二维矩阵是本方案的标志性元素。红色单元格只表示高风险身份字段命中，橙色单元格表示待复核线索，中性重复保持灰蓝。选择单元格后同时高亮行、列和左侧关联文件，底部证据抽屉展示原始值和解析器。

窄屏下矩阵允许水平滚动，投标人列头与字段首列保持粘性。选择和扫描阶段使用同一左侧文件树，使进入结果后空间模型不发生突变。

### 取舍

优势是专业性和数据密度最高；代价是首次上手成本最大。为控制复杂度，首屏只展示最能解释结论的 8–12 个字段，完整字段放在元数据明细页，不把所有 148 条记录塞进矩阵。

## 三套方案的差异边界

三套不能退化成换皮：

| 状态 | A：引导式 | B：结论先行 | C：证据矩阵 |
| --- | --- | --- | --- |
| 选择目录 | 五步轨道解释闭环 | 简洁任务陈述和隐私承诺 | 左侧目录树预览空间模型 |
| 扫描中 | 当前步骤沿轨道推进 | 中央阶段摘要，完成后进入报告 | 文件树逐项完成，右侧显示解析队列 |
| 报告 | 完成面板 + 四类任务卡 | 完整风险结论 + 证据时间线 | 投标人 × 字段命中矩阵 |
| 元数据 | 步骤 05 下的文档卡浏览 | 从结论直接定位字段 | 矩阵与证据抽屉联动 |

三套仍共享同一个词汇表、风险分类、模拟数据和状态机，防止因为内容不同而误判视觉方案优劣。

## 状态与数据流

```text
empty
  ├─ 载入演示项目 ──> ready
  └─ 选择本机目录 ──> validating ──> ready | selection-error

ready ──> scanning ──> report
             ├─ stop ──> stopped ──> ready
             └─ simulated-error ──> scan-error ──> ready

report <──> metadata
  └─ 重新选择 ──> empty

任意状态 ── 切换版本 ──> 同一状态的另一种布局
```

单一状态控制器拥有当前版本、业务状态、目录摘要、进度、报告筛选、展开项和元数据筛选。三种 Renderer 只消费状态和发出语义动作，不各自维护不一致的数据副本。

## 失败、边界与空状态

- 没有支持的 PDF、Word 或 Excel：说明支持格式，并允许重新选择或载入演示项目。
- 根目录没有一级投标人目录：显示边界提醒，根目录文件不参与跨投标人判断。
- 目录 API 不受支持：禁用本机目录动作，不影响演示项目。
- 用户取消目录选择：保持原页面，不显示错误。
- 扫描停止：显示可恢复状态，不生成半成品结论。
- 模拟扫描失败：明确指出是原型演示状态，并提供重试；不得伪装成真实解析错误。
- 筛选无结果：说明当前筛选没有命中，并提供清除筛选动作。
- 零风险演示：可通过隐藏的“演示场景”菜单切换，用成功语义显示“未发现跨投标人高风险身份痕迹”，不写“确认不存在串标”。

## 可访问性与响应式

- 使用真实 `button`、`input`、`progress`、`table` 或等效可访问语义。
- 所有键盘可达控件显示规范的 `2px` 主色焦点环和 `2px` 偏移。
- 扫描阶段使用 `aria-live="polite"`，错误使用 `role="alert"`。
- 图标按钮必须有可见 Tooltip 或 `aria-label`。
- 不依赖红绿颜色单独传达风险，必须同时显示文字和图标。
- 默认验收尺寸为 1440×900，同时验证 1280×800 和 1024×720。
- 小于 900px 时 A、B 改为单列，C 保留带粘性表头的横向矩阵；目标仍是桌面应用，不增加移动端专属功能。

## 视觉独特性自检

初稿最容易落入“企业蓝 + KPI 卡片网格”的通用后台模板。为避免这一点，设计做出以下针对主题的修正：

- A 的核心不是通用侧栏，而是可验证的核验步骤轨道；编号只用于真实顺序。
- B 的核心不是大数字，而是一句完整可审计结论和解释可信度的三引擎证据面板。
- C 的核心不是普通数据表，而是元数据字段与投标主体的二维取证矩阵。
- 三套都不使用大面积蓝色渐变、玻璃拟态、无意义图表、发光网格、装饰性曲线或 emoji。
- 每套只在一个地方承担视觉风险，其余区域保持规范要求的克制与精确。

## 验收与测试

使用原生 Playwright 对静态文件执行浏览器验收：

1. 入口可以进入 A、B、C，三个版本均能直接加载，无控制台错误。
2. 每个版本都能完成演示项目选择、开始、停止、重新开始、完成扫描、进入报告、进入元数据和返回报告。
3. 在报告与元数据状态切换版本后，业务状态与筛选不丢失。
4. 高风险、待复核和全部筛选返回确定的条目数量。
5. 元数据按投标人、文本和重复项筛选可组合使用。
6. 修改 `--primary` 后主按钮、链接、激活态、深色面板强调色和页头柔光同步变化，语义红橙绿保持不变。
7. `prefers-reduced-motion: reduce` 下没有持续位移动画，扫描状态仍清楚。
8. 键盘可以完成主要演示路径，焦点环可见，命中区不小于 28px。
9. 在 1440×900、1280×800 和 1024×720 截取每套的选择、扫描、报告和元数据关键截图。
10. 视觉走查确认浅色卡片零阴影、柔光不越过页头、图标全部来自注册表、主色没有被滥用。

## 明确不做

- 不调用 Python、Java、Apache Tika、POI、PDFBox 或 ExifTool。
- 不读取本机文档正文，不生成真实元数据，不上传文件。
- 不修改 `desktop/src/renderer/`、主进程、Preload、正式状态机或现有测试。
- 不实现真实报告导出、打印、密码处理或持久化项目管理。
- 不把原型页面宣称为已经完成的正式 Electron 界面。

## 完成定义

完成时，用户可从一个静态入口连续体验三套完整原型，在相同数据和相同状态下切换比较；每套都严格使用给定设计规范，并且在信息架构、首屏重心和证据下钻方式上具有可辨认的独立设计。原型通过自动交互测试、无控制台错误检查、键盘与减少动效检查，并提供三套报告页和关键流程截图供快速评审。
