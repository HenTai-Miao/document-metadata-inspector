## 页面唯一任务

结果页只负责呈现跨投标人的异常关系及其证据。文件总数、元数据总数、解析器运行次数等覆盖性数字不再与风险结论争夺首屏；完整文档元数据仍由“元数据明细”页面承载。

页面使用“风险项为行、涉险公司为列”的二维矩阵：

```text
┌ 顶栏：品牌 / 当前目录 / 风险报告 / 元数据明细 / 重新核验 ┐
├───────────────────────────────────────────────────────┤
│ 风险报告 · 仅显示异常项                                │
│ 8 项风险涉及 3 家公司                                  │
│ 高风险 2 · 待复核 6 · 未涉险公司已隐藏                 │
├──────────────────────────────────┬────────────────────┤
│ 风险项 / 命中值 │ 公司 A │ 公司 B │ 公司 C │ 当前风险证据       │
│ 公司 / 某值     │  命中  │  命中  │   —    │ 风险等级           │
│ 作者 / 某值     │  命中  │  命中  │   —    │ 字段与命中值       │
│ 模板 / 某值     │  命中  │  命中  │  命中  │ 公司及证据文件     │
│ …               │        │        │        │ 证据文件总数       │
└──────────────────────────────────┴────────────────────┘
```

矩阵是本页唯一的视觉主角。右侧深色证据面板是唯一使用投影的区域，用来解释当前选中的矩阵行；页面不再使用时间轴、统计卡片组或铺满首屏的文件标签。

## 信息范围与排序

### 风险行

风险行只来自：

1. `ScanResult.personTraces`，显示为“高风险”。
2. `ScanResult.cautionTraces`，显示为“待复核”。

高风险行始终排在待复核行之前。每个等级内部保持结果中的稳定顺序，不自行按文字或时间二次排序，避免改变证据序列。

每行显示：

- 风险等级，通过红色或橙色竖标、文字和命中方块共同表达，不仅依赖颜色。
- 风险字段，复用现有 `traceFieldLabel()` 中文映射。
- 原始命中值，直接使用 `TraceSummary.value`；时间、版本号、数字和属性值使用等宽字体，不补造日期、时区或缺失值。
- 公司命中关系，按 `TraceSummary.groupIds` 与公司列的交集计算。

同一风险即使关联多份文档，也只占一行。文件数量和文件名进入右侧证据面板，不在矩阵主表中重复铺开。

### 涉险公司列

公司列是全部显示风险行 `groupIds` 的有序并集，并与 `ScanResult.groups` 中 `kind === "bidder"` 的组相交：

- 使用 `ScanResult.groups` 的原始顺序，保证不同渲染之间稳定。
- 只显示至少命中一个高风险或待复核项的公司。
- 根目录文件组和完全未命中风险的投标人不生成列。
- 公司名使用现有 `buildGroupNames()` 结果；长名称允许两行显示，并通过 `title` 暴露完整名称。

一个单元格在当前风险的 `groupIds` 包含该公司 ID 时显示“命中”；否则显示中性破折号。破折号只表达“该风险未涉及该公司”，不把它渲染为绿色“安全”状态。

### 首屏结论

主标题使用完整结论句：

> 8 项风险涉及 3 家公司

其中：

- 风险项数量为两类 trace 数量之和。
- 公司数量为涉险公司列数量。
- 只显示实际存在的等级计数；例如没有高风险时不显示“高风险 0”。
- 使用辅助说明“未涉险公司已隐藏”，不列出任何无异常公司或通过字段。
- 目录名和核验时间保留在标题下方的低层级元信息中。

投标人数、文件数和元数据条数从结果页首屏移除。这些数字不解释风险关系，仍可在目录确认或元数据明细页面查看。

## 选中与证据联动

### 默认选中

首次渲染时默认选中第一条高风险；没有高风险时选中第一条待复核。选中行使用 `--primary-weak-2` 浅底，风险语义色不改变。

### 操作方式

- 风险项第一列使用原生 `<button type="button">` 承载“字段 + 命中值”，按钮视觉上与表格行融合。
- 点击该按钮切换当前风险，更新行选中态和右侧证据面板。
- 按钮的可访问名称包含字段和值，例如“查看公司：宏达建设集团有限公司的证据”。
- 不向全局 `AppState` 增加只服务于当前 DOM 的选中字段；选择状态由 `renderResult()` 创建的局部交互持有，重新进入页面时恢复默认选中。

### 证据面板

证据面板显示：

1. 当前风险等级。
2. 字段中文名。
3. 原始命中值。
4. 按公司分组的证据文件名。
5. 证据文件总数。

证据文件通过现有文档映射从 `TraceSummary.documentIds` 解析，并按结果公司顺序分组。面板只显示文件名，不显示绝对路径、原始异常、文档正文或未参与当前风险的文件。找不到映射的文档 ID 时跳过该条展示，并保留可用证据；若全部无法映射，显示“没有可显示的文件证据”，不泄露内部 ID。

## 视觉系统

页面严格使用提供的设计规范：

- `--primary: #034ed6` 只用于顶栏激活态、选中行浅底和已有主按钮。
- `--danger: #c93438` / `--danger-weak: #fdeeee` 只表示高风险。
- `--warning: #a85c00` / `--warning-weak: #fdf3e4` 只表示待复核。
- `--ink: #141928`、`--sub: #5d6579`、`--faint: #6b7489` 承担正文层级。
- `--line: #e8eaf0` 用于矩阵外框，`--line-soft: #f0f2f7` 用于行列分隔。
- 右侧证据面板使用 `--dark: #0e1226`、14px 圆角和规范中的唯一深色面板投影。
- 浅色矩阵零投影；页面主体纯白；柔光只出现在页头并自然过渡到白色。
- 字体沿用中文系统栈；字段值、日期、数字和计数使用 `--mono` 与 `tabular-nums`。
- 图标只从注册表复制已有 `i-logo`、`i-alert`、`i-node`、`i-file` 等需要的 `<symbol>`，不使用 emoji、图标字体或新造图标。

不使用大面积语义色背景、玻璃拟态卡片、发光、呼吸动画、装饰性图表或无含义编号。

## 响应式与大量公司

- 默认桌面布局为矩阵和 282px 证据面板并排。
- 当可用宽度不超过 1150px 时，矩阵占满一行，证据面板落到矩阵下方；风险主表不得因为侧栏而裁切。
- 矩阵第一列最小宽度为 300px；每个公司列最小宽度为 150px。
- 涉险公司较多时，矩阵容器局部横向滚动，第一列保持粘性；页面本身不产生横向溢出。
- 公司列头最多显示两行，超出使用省略号与 `title`。
- 证据面板在下方时，公司证据可在宽屏形成多列，在窄屏回到单列。
- 正式桌面验收尺寸为 1440×900、1280×800 和 1024×720。

## 无风险与边界状态

### 完全无风险

当高风险和待复核均为空时，不生成矩阵、公司列、通过项列表或“公司名无重复”等标签。页面只显示一个克制的结果提示：

> 未发现需关注的跨投标人风险

提示下可保留目录名和核验时间，不展开任何无异常明细。这既避免空白页面，也符合“完全隐藏无异常内容”的确认口径。

### 只有一种风险等级

- 只有高风险时只显示高风险数量与高风险行。
- 只有待复核时只显示待复核数量与待复核行。
- 不渲染另一个等级的零值、空分区或说明。

### 空公司并集

若 trace 存在但没有任何可匹配的 bidder 组，页面不伪造公司列。此状态使用现有失败关闭原则，显示“风险关系缺少可显示的投标人信息”，并允许进入元数据明细检查来源；不把它降级为“无风险”。正常适配器已过滤少于两个投标人组的 trace，这一分支用于防御不一致输入。

## 测试设计

### 单元测试

`buildRiskMatrixModel()` 至少覆盖：

1. 高风险在前、待复核在后，等级内部顺序稳定。
2. 涉险公司列只包含风险 `groupIds` 的 bidder 有序并集。
3. 未涉险公司和根目录文件组不生成列。
4. 每个矩阵单元格按精确 group ID 命中，不按公司名称猜测。
5. 证据文件按公司分组，且只包含当前 trace 的 `documentIds`。
6. 缺失文档映射不会暴露内部 ID，也不会影响其他证据。
7. 空 trace 返回明确的零风险模型，不产生无异常明细。

### 浏览器与视觉验证

1. 默认选中第一条高风险，并显示正确公司和证据文件。
2. 点击待复核行后，行选中态、风险等级、值、公司和文件同步更新。
3. 键盘可聚焦并触发每个风险按钮，焦点环可见。
4. 页面不出现无风险公司、无异常字段或通过项标签。
5. 1440×900、1280×800、1024×720 下没有文字遮挡、证据面板挤压或页面级横向溢出。
