# 退出五类问题检测设计

## 背景与目标

当前跨投标人比较器会把经理、公司、签名人、路径用户名和模板元数据视为身份痕迹，桌面结果页因此固定显示对应的五个问题标签。产品决定不再使用这五类信息判断问题，但仍需保留其原始取证价值。

本设计让以下五类字段退出问题检测链路：

- `manager`：经理检测；
- `company`：公司检测；
- `signer_identity` 与其来源别名 `signature_signer_name`：签名人检测；
- `username_path_trace`：路径用户名检测；
- `template`：模板检测。

变更后，正式结果页只保留六类问题标签：创建人、修改人、批注人、修订人、创建时间和修改时间。

## 范围

### 检测规则

Python 比较器的身份字段白名单不再接纳上述五类字段。扫描器和各解析器仍然提取这些字段，文档完整证据、按需详情和导出数据仍然保留它们。

新扫描生成的 `TraceMatch` 不得仅因上述五类字段在不同投标人之间相同而产生。保留字段的精确跨投标人比较行为不变。

### 桌面结果页

问题标签定义从十一项收窄为以下六项，并保持此顺序：

1. 创建人检测；
2. 修改人检测；
3. 批注人检测；
4. 修订人检测；
5. 创建时间检测；
6. 修改时间检测。

风险数、无风险数、公司关系数和页面导航均只基于这六项计算。旧报告或预览报告即使包含已退出字段的 trace，结果页也忽略这些 trace；若一个旧 trace 同时包含保留字段和已退出字段，只把它归入对应的保留标签。

### 元数据明细

元数据明细继续展示解析器实际提取的经理、公司、签名信息、路径用户名和模板字段。已有中文字段翻译、详情文件和完整证据文件不删除，也不改变其序列化结构。

## 兼容性

- 不修改 `DocumentReport`、`ComparisonReport`、桌面摘要或详情的 schema 版本。
- 不迁移或重写历史报告。
- 新程序可读取历史报告；历史报告中的五类 trace 只是不再进入问题标签视图。
- 公共扫描和导出仍保留原始元数据，只有问题比较候选集合发生收窄。

本设计只取代 `2026-08-10-problem-label-evidence-report-design.md` 中固定十一类标签和这五类字段参与问题检测的要求；其证据层级、公司组合、文件归属、失败关闭和响应式展示要求继续有效。

## 安全与错误处理

此次变更不会放宽文件读取、格式识别、解析预算、网络隔离、路径身份或结果文件校验。解析失败和不安全输入仍使用现有失败关闭合同。已退出字段只是不会参与问题判断，不会被伪装成“检测通过”。

无法识别的问题 trace 继续由视图模型忽略，不显示内部 ID、原始路径或异常细节。保留字段的缺失证据处理方式不变。

## 测试设计

实施必须按测试驱动顺序完成：

1. Python 比较器测试先证明经理、公司、签名人、路径用户名和模板仍会产生 match，形成 RED；实现后要求它们不再产生 match。
2. 同一测试覆盖创建人、修改人、批注人、修订人、创建时间和修改时间仍可产生预期 match。
3. 桌面视图模型测试先期望固定六个标签并验证顺序、风险数和无风险数，形成 RED。
4. 桌面测试传入只含已退出字段的历史 trace，要求六个标签保持无风险且不泄漏该 trace；混合 trace 仍进入保留标签。
5. 元数据明细测试证明经理、公司、签名人、路径用户名和模板的字段翻译与展示仍然存在。
6. 浏览器验收把固定标签数量和文案从十一项更新为六项，并继续验证证据层级和无风险状态。
7. 完成 Python 全量测试、Ruff、格式、BasedPyright、锁文件和构建，以及桌面全量测试、类型检查、Lint、格式和生产构建。

## 成功标准

- 新扫描不会为五类已退出字段生成问题 match。
- 正式结果页和导航中不存在五个已退出问题标签。
- 六个保留标签顺序和检测行为不变。
- 历史 trace 不会让已退出标签重新出现。
- 五类原始元数据仍存在于文档证据和按需元数据明细中。
- 报告 schema、安全边界和大批次流式结果方案不发生回退。
